MMA Go C ABI wrapper
====================

The package `github.com/Edestuss0/MMA-Network-protocol/cabi` calls the existing
Rust C ABI in `include/mma.h` through purego. The public header and Rust C ABI
are not changed, and the protocol implementation remains in Rust.

Using the package
-----------------
Consumers need Go 1.25+ and a supported OS/architecture (Windows amd64, Linux
amd64, macOS amd64 or arm64). They do not need Rust, Cargo, CGO, GCC, MinGW or
MSVC. On the first native call, the package downloads the Rust shared library plus a small callback bridge for the selected module
release, verifies the ZIP SHA-256 checksum, and caches both files in the
user's OS cache directory.

Example consumer setup:

    go get github.com/Edestuss0/MMA-Network-protocol/cabi@v0.1.0

Then import it normally:

    import "github.com/Edestuss0/MMA-Network-protocol/cabi"

The version above is illustrative; use a version that has been published.

Environment variables
---------------------
MMA_NATIVE_VERSION  Override the native release tag. Useful for local testing.
MMA_NATIVE_DIR      Load prebuilt native files from a local directory instead
                    of downloading them. The directory must contain both files:
                    MMA.dll + mma_go_bridge.dll (Windows), libMMA.so +
                    libmma_go_bridge.so (Linux), or libMMA.dylib +
                    libmma_go_bridge.dylib (macOS).
MMA_NATIVE_REFRESH  Set to 1 to redownload the cached artifact before startup.

Publishing a release
--------------------
1. Push the code and the tag to GitHub, for example:

       git add .
       git commit -m "Add compiler-free Go bindings"
       git push origin master
       git tag v0.1.0
       git push origin v0.1.0

2. The workflow `.github/workflows/native-release.yml` builds precompiled
   Rust shared libraries and the C callback bridge for Windows amd64, Linux
   amd64, macOS amd64 and macOS arm64, then uploads each ZIP and SHA-256
   checksum to that GitHub release. The bridge exists only to adapt the route
   callback ABI for a CGO-free Go caller; `include/mma.h` and the Rust C ABI
   are unchanged.
3. Users import the `cabi` package. They do not run Cargo or compile C code.

The repository must have a release with the matching platform assets before
users can initialize the native API. While developing locally, build both the Rust shared library and matching callback bridge on the
developer machine, put both files in one folder and set MMA_NATIVE_DIR to that
folder, or wait for the GitHub release workflow to publish the artifacts.

Testing
-------
Regular Go-only tests:

    go test ./cabi

Native integration tests (requires local library or a published release):

    go test -tags native_integration ./cabi

No standalone Framer implementation is added in Go: the protocol framing and
server engine continue to run in Rust.
