MMA Go C ABI wrapper
====================

The `cabi` package calls the existing Rust C ABI declared in `include/mma.h`.
It does not reimplement the protocol or the Rust engine. A C compiler and cgo
are required to run the native implementation.

IMPORTANT: if `CGO_ENABLED=0`, Go selects `cabi/native_nocgo.go`. That file is
only a type-checking stub for IDEs and returns `cabi.ErrCGODisabled`; it does
not provide a working server. The real wrapper is in `cabi/native.go`.

Windows (64-bit, MinGW/GNU toolchain)
------------------------------------
1. Install a MinGW-w64 GCC that is on PATH, and verify `gcc --version` works.
2. Make the Go cgo toolchain match the Rust GNU target:

   go env -w CGO_ENABLED=1
   rustup target add x86_64-pc-windows-gnu
   cargo build --release --target x86_64-pc-windows-gnu

3. From the repository root in PowerShell:

   $env:PATH = "$PWD\target\x86_64-pc-windows-gnu\release;$env:PATH"
   go test ./cabi

The `PATH` entry is needed at runtime so Windows can load `MMA.dll`. Go's
architecture and Rust target must match. This configuration uses the GNU
Rust target because cgo's GCC linker does not generally link directly against
an MSVC-target library.

Linux
-----
From the repository root:

   cargo build --release
   export CGO_ENABLED=1
   export LD_LIBRARY_PATH="$PWD/target/release${LD_LIBRARY_PATH:+:$LD_LIBRARY_PATH}"
   go test ./cabi

macOS
-----
From the repository root:

   cargo build --release
   export CGO_ENABLED=1
   export DYLD_LIBRARY_PATH="$PWD/target/release${DYLD_LIBRARY_PATH:+:$DYLD_LIBRARY_PATH}"
   go test ./cabi

API overview
------------
- `DefaultServerConfig`, `NewServer`, `Server.Start`, `Server.Stop`,
  `Server.Close`, `Server.BoundPort`.
- `Server.RegisterRoute` / `Server.Handle` for request-response routes.
- `Server.RegisterChannelHandler` for messages on channel routes.
- `Server.GetHandle`, `ServerHandle.SendToChannel`, `ServerHandle.ChangeConfig`.
- `ResponseBuilder.SetStatus`, `SetPayload`, `AddOption`.

Register routes before starting the server. Rust calls Go handlers through a C
trampoline and `runtime/cgo.Handle`; request memory is copied into Go-owned
values during the callback. Do not retain `ResponseBuilder` beyond the route
handler. Handlers can run concurrently and must synchronize their own shared
state.
